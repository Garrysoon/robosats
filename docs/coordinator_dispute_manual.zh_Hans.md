# 🛡️ RoboSats 协调者争议仲裁标准规程 (Dispute SOP)

本文档是协调者系统管理员和仲裁员的标准作业规程（Standard Operating Procedure — SOP），规范了证据链分析、密码学校验及 Django 控制台仲裁处置动作。

---

## 1. 仲裁基本原则

1. **密码学证据高于口头陈述：** 数学与密码学证明（银行 DKIM 签名、BIP-340 施诺尔签名、闪电网络有效原象、链上交易记录）具有绝对优先权，高于截图、普通 PDF 凭证及文字说明。
2. **零身份穿透与隐私保护（Zero-KYC）：** 仲裁员**绝不要求**用户提供身份证件、手持自拍、银行卡照片或人脸视频。仲裁仅基于支付事实证据、`.eml` 邮件头、账单对账明细和节点状态日志。
3. **公正透明与响应超时：** 发生争议时，三方加密聊天室中的各方均有 **24 小时**举证期。若一方在时限内不予回应，判定由按时应答的守约方胜诉。
4. **结算不可逆性：** 在 Django 控制台执行仲裁裁决动作后，资金将立即通过闪电网络或链上交易结算，操作不可撤回。

---

## 2. 争议介入初查清单

当订单进入争议状态 `Disputed` (`is_disputed = True`) 时：

1. **在 Django 控制台中定位订单：**
   * 进入 `RoboSats Admin` → `Orders` → 根据订单编号检索。
2. **核查 `Logs` 事件流：**
   * 订单何时创建？
   * 挂单方与吃单方的保证金（`Maker bond`, `Taker bond`）是否均已锁定？
   * 交易托管保证金（`Trade escrow`）是否已锁定？
   * 争议发生于买家标记「法币已付（Fiat Sent）」之前还是之后？
3. **检查控制台中的安全徽章状态：**
   * **`Bank Receipt (DKIM)`**：系统是否已完成银行邮件签名的自动校验？
   * **`F2F Cash`**：该交易是否为现金面对面交易协议？
4. **进入三方 PGP 加密聊天室：**
   * 表明仲裁员身份，要求发起争议方说明具体原因。

## 3. 按交易类型执行仲裁

### 场景 A：银行转账与电子法币支付（银行转账、SEPA、Revolut 等）

#### 1. 防三角欺诈校验（Anti-Triangle）
* 核对支付金额是否与包含便士随机数（Penny Randomization）的精准金额一致。
* 检查转账附言中是否注明了 `ROBO-<order.id>`。若附言缺失或填写了其他编号，需警惕第三方洗钱或三角诈骗。

#### 2. DKIM 银行凭证验证
普通截图与 PDF 极易被图像软件篡改伪造。
* **对买家的举证要求：** 要求买家提供银行发送的原始确认邮件文件（`.eml` 格式）。
* **内置验证模块校验 (`api/dkim_verifier.py`)：**
  * 若控制台显示绿色徽章 **`✓ [domain] PASS`**：
    * 证实邮件确实由该银行邮件服务器的私钥（RSA/Ed25519）签名，且金额与附言编号未被篡改。
  * 若显示黄色徽章 **`⚠ [domain] (FAIL)`**：
    * 签名无效或发件方域名不在受信任银行列表（`TRUSTED_BANK_DOMAINS`）中，该凭证视为无效。

#### 3. 裁决对照表：
| 争议情形 | 证据情况 | 仲裁处置动作 |
| :--- | :--- | :--- |
| 买家提供有效 `.eml` 且 DKIM PASS，卖家拒绝放行 BTC | DKIM 验证通过，金额与 `ROBO-<id>` 一致 | **`Solve dispute: buyer wins`**（或 **`successful trade`**）。比特币发放给买家，罚没扣除卖家保证金。 |
| 卖家声明未收到款，买家在 24 小时内未提供有效凭证 | 无法证明法币已转出 | **`Solve dispute: seller wins`**。罚没扣除买家保证金，托管资金退还卖家。 |
| 银行风控冻结（反洗钱/风控拦截），法币已原路退回买家 | 双方均证实法币已原路退回 | **`Solve dispute: return everything`**。保证金与托管金无罚金全额退回原账户。 |

## 4. 控制台快捷操作按钮指南

| 操作按钮 (Action) | 资金划转说明 | 适用场景 |
| :--- | :--- | :--- |
| **`Solve dispute: maker wins`** | 挂单方获得交易金额 + 自身保证金 + 吃单方保证金。吃单方保证金被扣除。 | 吃单方违规、试图欺诈或失联超时。 |
| **`Solve dispute: taker wins`** | 吃单方获得交易金额 + 自身保证金 + 挂单方保证金。挂单方保证金被扣除。 | 挂单方违规或在确认收到法币后拒绝放行。 |
| **`Solve dispute: successful trade`** | 交易按正常成交结算：买家获得 BTC，双方全额退还保证金。 | 买家已证实付款（DKIM PASS），卖家因意外掉线未手动确认。 |
| **`Solve dispute: return everything`** | 托管款项退还卖家，保证金退还双方，无任何罚款。 | 不可抗力、银行系统故障，双方协商一致无异议取消。 |
| **`Close public order`** | 从公开订单簿中下架/取消该挂单。 | 异常僵尸挂单、垃圾订单或运维人工下架。 |
