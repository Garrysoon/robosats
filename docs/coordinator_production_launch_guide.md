## 1. Архитектура и системные требования

### Стек сервисов координатора
- **Backend**: Python 3.12+ / Django 5+ / ASGI Daphne / Channels (WebSockets).
- **База данных**: PostgreSQL 15+ (транзакционный CAS-уровень, защита от race condition).
- **Очереди и кеш**: Redis 7+ (каналы чата, брокер Celery).
- **Сеть Lightning**: LND (v0.18+) или Core Lightning (CLN) с поддержкой Hold Invoices.
- **Приватность**: Tor v3 Onion Service для скрытого взаимодействия пиров.
- **Интерфейс оператора**: Django Unfold Ops Cockpit с русской локализацией и разделением ролей.

### Минимальные требования к серверу
- **ОС**: Ubuntu 22.04 / 24.04 LTS (или Debian 12).
- **CPU**: 4 ядра.
- **RAM**: 8 ГБ (минимум 16 ГБ при запуске полной ноды bitcoind на том же сервере).
- **Диск**: NVMe SSD от 200 ГБ (без учета полного блокчейна Bitcoin).

## 2. Пошаговое развертывание в Docker

### Шаг 1: Клонирование репозитория
```bash
git clone https://github.com/Garrysoon/robosats.git /opt/robosats
cd /opt/robosats
```

### Шаг 2: Создание конфигурации окружения
```bash
cp .env-sample .env
# Отредактируйте .env в соответствии с разделом 3
nano .env
```

### Шаг 3: Сборка и первый запуск контейнеров
```bash
docker-compose up -d
```

### Шаг 4: Применение миграций базы данных
```bash
docker exec -it django-dev python3 manage.py migrate
```

### Шаг 5: Компиляция каталога локализации
```bash
docker exec -it django-dev python3 compile_translations.py
```

### Шаг 6: Создание учетной записи главного администратора
```bash
docker exec -it django-dev python3 manage.py createsuperuser
```
> [!IMPORTANT]
> Имя пользователя суперпользователя ОБЯЗАНО совпадать со значением переменной `ESCROW_USERNAME` в файле `.env` (по умолчанию `admin`).

## 3. Конфигурация переменных окружения (.env)

Ключевые параметры координатора:

| Переменная | Описание | Рекомендуемое значение |
|---|---|---|
| `COORDINATOR_ALIAS` | Публичный псевдоним ноды | `MySovereignCoordinator` |
| `NETWORK` | Сеть Bitcoin | `mainnet` (или `testnet`) |
| `SECRET_KEY` | Криптографический ключ сессий Django | Случайная строка 64+ символов |
| `ESCROW_USERNAME` | Логин координатора для депонирования | `admin` |
| `LANGUAGE_CODE` | Язык панели по умолчанию | `ru` |
| `LNVENDOR` | Тип Lightning-ноды | `LND` |
| `LND_GRPC_HOST` | Хост gRPC ноды LND | `lnd:10009` |
| `LND_DIR` | Путь к директории LND | `/lnd` |
| `MACAROON_PATH` | Путь к макаруну | `data/chain/bitcoin/mainnet/admin.macaroon` |
| `MIN_TRADE` | Минимальный объем сделки (sats) | `20000` |
| `MAX_TRADE` | Максимальный объем сделки (sats) | `5000000` |
| `FEE` | Комиссия координатора | `0.002` (0.2%) |
| `DEFAULT_BOND_SIZE` | Размер страхового залога (%) | `3.0` |
| `FIAT_EXCHANGE_DURATION` | Окно оплаты покупателем (часы) | `24` |
| `CSRF_TRUSTED_ORIGINS` | Доверенные домены панели | `https://coord.example.com,http://localhost:8000` |

## 4. Инициализация LND-кошелька и прав доступа

Координатор RoboSats не требует полного `admin.macaroon`. В целях безопасности рекомендуется создать ограниченный макарун:

```bash
docker exec -it lnd-dev lncli bakemacaroon \
  --save_to=/lnd/robosats.macaroon \
  uri:/verrpc.Versioner/GetVersion \
  uri:/lnrpc.Lightning/DecodePayReq \
  uri:/lnrpc.Lightning/GetInfo \
  uri:/lnrpc.Lightning/EstimateFee \
  uri:/lnrpc.Lightning/WalletBalance \
  uri:/lnrpc.Lightning/ChannelBalance \
  uri:/lnrpc.Lightning/SendCoins \
  uri:/invoicesrpc.Invoices/CancelInvoice \
  uri:/invoicesrpc.Invoices/SettleInvoice \
  uri:/invoicesrpc.Invoices/AddHoldInvoice \
  uri:/invoicesrpc.Invoices/LookupInvoiceV2 \
  uri:/routerrpc.Router/SendPaymentV2 \
  uri:/routerrpc.Router/TrackPaymentV2 \
  uri:/signrpc.Signer/SignMessage
```
Укажите созданный макарун в `.env`:
```env
MACAROON_PATH=robosats.macaroon
```

## 5. Настройка почтового ящика для чеков (IMAP + DKIM)

Трейдеры могут отправлять банковские выписки (Т-Банк, Сбербанк, Альфа, Райффайзен) прямо из мобильных приложений на ящик координатора.

### Пошаговая привязка ящика:
1. Зарегистрируйте рабочий почтовый ящик (например, на Яндекс 360: `receipts@mycoord.org`).
2. В настройках безопасности почтового сервиса создайте **Пароль приложения (App Password)** для IMAP.
3. Откройте панель администратора: **`http://localhost:8000/coordinator/`**.
4. Перейдите в **`🏦 БАНКОВСКИЕ ЧЕКИ И ФИНАНСЫ > Почтовые ящики IMAP`** и нажмите **`Добавить`**.
5. Заполните поля:
   - **Хост IMAP**: `imap.yandex.ru`
   - **Порт IMAP**: `993`
   - **Логин / Email**: `receipts@mycoord.org`
   - **Пароль / Токен приложения**: ваш сгенерированный App Password
   - **Использовать SSL/TLS**: `Включено (True)`
   - **Папка ящика**: `INBOX`
   - **Публичный email для чеков**: `receipts@mycoord.org` (отображается трейдерам)
   - **Активен**: `Включено`
6. В списке ящиков выберите созданную запись, в выпадающем списке «Действие» выберите **`🔌 Проверить IMAP-подключение`** и нажмите кнопку **`Выполнить`**.
7. Убедитесь в появлении зеленого сообщения об успешной аутентификации.

> [!NOTE]
> При проверке цифровой подписи библиотека `dkimpy` обращается к DNS за TXT-записью `_domainkey` банка. Сервер координатора должен иметь возможность отправлять стандартные DNS-запросы на порт 53.

## 6. Запуск фоновых демонов автоматизации

Для непрерывной автономной работы запустите два процесса:

### А. Демон опроса банковской почты (`watch_receipt_emails`)
Опрашивает почту каждые 60 секунд, извлекает чеки и PDF, валидирует DKIM и привязывает к сделке:
```bash
# Тестовый разовый прогон:
docker exec -it django-dev python3 manage.py watch_receipt_emails --once

# Непрерывный фоновый запуск:
docker exec -d django-dev python3 manage.py watch_receipt_emails --interval 60
```

### Б. Демон авто-разрешения споров (`auto_resolve_disputes`)
Каждые 5 минут проверяет SLA молчания (24 часа) и исполняет авто-резолв после 30 минут вето при валидном DKIM:
```bash
docker exec -d django-dev python3 manage.py auto_resolve_disputes --interval 300 --silence-hours 24 --dkim-veto-minutes 30
```

## 7. Регламент разрешения споров в Dispute Cockpit

При возникновении диспута откройте раздел **`🚨 АРБИТРАЖ И СПОРЫ > Споры и сделки`** и кликните на проблемный ордер. Вверху отобразится **Пульт арбитража (Dispute Cockpit)**:

1. **Если статус `✓ БАНКОВСКИЙ ЧЕК ВЕРИФИЦИРОВАН (DKIM PASS)`**:
   - Система подтвердила, что письмо отправлено серверами банка, сумма и код `ROBO-<id>` в точности совпадают.
   - Окно вето составляет 30 минут. Если продавец молчит или не предоставил доказательств отзыва платежа — примените действие в 1 клик: **`⚡ Применить рекомендуемый вердикт арбитража`** (сделка признается успешной, сатоши выплачиваются покупателю).
2. **Если одна из сторон молчит более 24 часов (SLA Silence Timeout)**:
   - ИИ-движок выставляет вердикт `MAKER WINS` или `TAKER WINS` со 100% уверенностью.
   - Нажмите действие в 1 клик для начисления компенсации активной стороне.
3. **Если спор сложный (нет чека, обе стороны спорят)**:
   - Проверьте окна заявлений сторон в пульте арбитража.
   - Запросите у покупателя отправку чека из приложения банка на официальный IMAP-ящик.
   - При взаимном согласии сторон или ошибке платежа выберите **`Разрешить спор: возврат всех залогов`** (`return_everything`).

## 8. Устранение неполадок (Troubleshooting)

### Ошибка: `Authentication failed` при проверке IMAP
- Убедитесь, что используется именно **Пароль приложения**, а не основной пароль от учетной записи.
- Для Яндекс Почты включите доступ по протоколу IMAP в настройках почтового клиента.

### Ошибка: `DKIM verification failed: body hash mismatch`
- Банковское письмо было переслано сторонним почтовым клиентом с изменением HTML-разметки или кодировки.
- Попросите покупателя воспользоваться кнопкой «Отправить квитанцию на email» непосредственно внутри приложения банка.

### Как перезапустить локальный веб-сервер и админку
```bash
python manage.py runserver 127.0.0.1:8000 --settings=robosats.settings_dev_lite
```
Вход в панель оператора: [http://127.0.0.1:8000/coordinator/](http://127.0.0.1:8000/coordinator/) (логин `admin`, пароль `admin12345`).
