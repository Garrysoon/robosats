# 🛡️ RoboSats 協調者爭議仲裁標準規程 (Dispute SOP)

本文件為協調者系統管理員與仲裁員之標準作業規程（Standard Operating Procedure — SOP），規範證據鏈分析、密碼學校驗以及 Django 控制台仲裁處置動作。

---

## 1. 仲裁基本原則

1. **密碼學證據高於口頭陳述：** 數學與密碼學證明（銀行 DKIM 簽名、BIP-340 施諾爾簽名、閃電網絡有效原像、鏈上交易記錄）具備絕對優先權，高於螢幕截圖、普通 PDF 憑證及文字說明。
2. **零身份穿透與隱私保護（Zero-KYC）：** 仲裁員**絕不要求**用戶提供身分證件、手持自拍、銀行卡照片或人臉視訊。仲裁僅基於支付事實證據、`.eml` 郵件標頭、對賬單明細及節點狀態日誌。
3. **公正透明與回應超時：** 發生爭議時，三方加密聊天室中的各方均有 **24 小時**舉證期。若一方在時限內未予回應，判定由按時應答之守約方勝訴。
4. **結算不可逆性：** 於 Django 控制台執行仲裁裁決動作後，資金將立即透過閃電網絡或鏈上交易結算，操作不可撤回。

---

## 2. 爭議介入初查清單

當訂單進入爭議狀態 `Disputed` (`is_disputed = True`) 時：

1. **於 Django 控制台定位訂單：**
   * 進入 `RoboSats Admin` → `Orders` → 根據訂單編號檢索。
2. **核查 `Logs` 事件流：**
   * 訂單何時建立？
   * 掛單方與吃單方之保證金（`Maker bond`, `Taker bond`）是否均已鎖定？
   * 交易託管保證金（`Trade escrow`）是否已鎖定？
   * 爭議發生於買家標記「法幣已付（Fiat Sent）」之前或之後？
3. **檢查控制台中的安全徽章狀態：**
   * **`Bank Receipt (DKIM)`**：系統是否已完成銀行郵件簽名之自動校驗？
   * **`F2F Cash`**：該交易是否為現金面對面交易協議？
4. **進入三方 PGP 加密聊天室：**
   * 表明仲裁員身分，要求發起爭議方說明具體原因。

## 3. 按交易類型執行仲裁

### 場景 A：銀行轉賬與電子法幣支付（銀行轉賬、SEPA、Revolut 等）

#### 1. 防三角欺詐校驗（Anti-Triangle）
* 核對支付金額是否與包含便士隨機數（Penny Randomization）之精準金額一致。
* 檢查轉賬備註中是否註明了 `ROBO-<order.id>`。若備註缺失或填寫了其他編號，需警惕第三方洗錢或三角詐騙。

#### 2. DKIM 銀行憑證驗證
普通截圖與 PDF 極易被圖像軟體篡改偽造。
* **對買家之舉證要求：** 要求買家提供銀行發送之原始確認郵件檔案（`.eml` 格式）。
* **內建驗證模組校驗 (`api/dkim_verifier.py`)：**
  * 若控制台顯示綠色徽章 **`✓ [domain] PASS`**：
    * 證實郵件確實由該銀行郵件伺服器之私鑰（RSA/Ed25519）簽名，且金額與備註編號未被篡改。
  * 若顯示黃色徽章 **`⚠ [domain] (FAIL)`**：
    * 簽名無效或寄件方網域不在受信任銀行清單（`TRUSTED_BANK_DOMAINS`）中，該憑證視為無效。

#### 3. 裁決對照表：
| 爭議情形 | 證據情況 | 仲裁處置動作 |
| :--- | :--- | :--- |
| 買家提供有效 `.eml` 且 DKIM PASS，賣家拒絕放行 BTC | DKIM 驗證通過，金額與 `ROBO-<id>` 一致 | **`Solve dispute: buyer wins`**（或 **`successful trade`**）。比特幣發放給買家，沒收扣除賣家保證金。 |
| 賣家聲明未收到款，買家於 24 小時內未提供有效憑證 | 無法證明法幣已轉出 | **`Solve dispute: seller wins`**。沒收扣除買家保證金，託管資金退還賣家。 |
| 銀行風控凍結（反洗錢/風控攔截），法幣已原路退回買家 | 雙方均證實法幣已原路退回 | **`Solve dispute: return everything`**。保證金與託管金無罰金全額退回原賬戶。 |

## 4. 控制台快捷操作按鈕指南

| 操作按鈕 (Action) | 資金劃轉說明 | 適用場景 |
| :--- | :--- | :--- |
| **`Solve dispute: maker wins`** | 掛單方獲得交易金額 + 自身保證金 + 吃單方保證金。吃單方保證金被扣除。 | 吃單方違規、企圖欺詐或失聯超時。 |
| **`Solve dispute: taker wins`** | 吃單方獲得交易金額 + 自身保證金 + 掛單方保證金。掛單方保證金被扣除。 | 掛單方違規或於確認收到法幣後拒絕放行。 |
| **`Solve dispute: successful trade`** | 交易按正常成交結算：買家獲得 BTC，雙方全額退還保證金。 | 買家已證實付款（DKIM PASS），賣家因意外斷線未手動確認。 |
| **`Solve dispute: return everything`** | 託管款項退還賣家，保證金退還雙方，無任何罰款。 | 不可抗力、銀行系統故障，雙方協商一致無異議取消。 |
| **`Close public order`** | 從公開訂單簿中下架/取消該掛單。 | 異常停滯訂單、垃圾訂單或運維人工下架。 |
